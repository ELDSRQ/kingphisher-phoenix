**Port correction:** the APIs listen on **8000/8001**, not 8080/8081. Earlier handoff notes and at
least one probe in this session used 8080/8081 and read the resulting connection refusal as an
outage. It was not. Use 8000/8001.

**Anchor cadence is event-driven, not clock-driven.** Sequence numbers advance in steps of 5 and a
file appears only when new audit events accumulate; on an idle stack hours can pass with no new
anchor. A stale newest-anchor timestamp is therefore *not* by itself evidence of a stopped worker —
check the process and the sequence, not the mtime.

**There are NO scale rules on any container app.** Verified 2026-09-08:
`properties.template.scale.rules` is `null` on all four, and there is no
`scale_rule`/KEDA configuration anywhere in `infrastructure/terraform`. Any reasoning that assumes
"a queue rule will wake it" is wrong — that assumption was written into the nightly job's orphan
detector and hid a real replica for four nights.

**The worker replica is doing necessary work.** `kp-worker supervise` runs every role in one
polling process, and four roles publish their own trigger messages from wall-clock timers *inside*
that process: retention (86400s), **audit-anchor (3600s)**, ingestion (86400s), mailbox (60s). At
zero replicas the interval elapses, nothing is enqueued, and no queue-depth rule could ever wake it
— the window is **dropped, not deferred**. Terraform pins `min_replicas = 1` for exactly this
reason. Only `delivery` is a pure consumer, which is why `isolate_delivery_worker` splits it out.

**The gap is the resume path, not the replica.** The nightly job sets every app to `min-replicas 0`
— correct overnight, since PostgreSQL stops moments later — but **nothing restores it**, and
`az postgres flexible-server start` alone does not. Only a terraform apply does. Tracked as
**OPS-003** in `docs/WAVE-BUILD-PLAN.md`; deferred to the next deploy because a replica is
currently running and nothing is being missed.

**Power model**

| Mechanism | Effect | Trigger |
|---|---|---|
| `azure-nightly-shutdown.yml` | on-demand backup → stop Postgres → apps to 0 → deallocate runner. Never starts anything. **Fails safe: no backup ⇒ no stop.** | automatic, 23:00 ET, armed (`NIGHTLY_AZURE_SHUTDOWN=enabled`) |
| `azure-idle.yml` / `azure-idle.sh stop` | **deep idle — terraform-destroys** ACR, Redis, Container Apps (~$101/mo) | manual, `confirm=IDLE`, staging reviewer gate |
| `azure-deploy.yml` | creates everything | manual, gated |
| `azure-idle.sh start` | resume — **Postgres FIRST, then apps** | manual |

Resume order matters: apps started against a stopped database fail their startup probes, which is
why operator/tracking revisions show `ActivationFailed` after a nightly stop.

### Known traps — do not relearn these

1. **`make test` runs none of the three gates.** Use `make lint`, `make typecheck`, and
   `scripts/run-hermetic-tests.sh all`. Most of this session's hidden failures came from gating on
   `make test`.
2. **Never `git add -A` in this repo.** It records `.claude/worktrees/*` as gitlinks. Now
   `.gitignore`d, but check what you staged.
3. **Never point `DATABASE_URL_TEST` at the `kingphisher` database.** The fixtures `DROP SCHEMA`.
   `scripts/run-postgres-tests.sh` now refuses a cluster hosting `kingphisher`/`_prod`/`_staging`
   (override `KP_POSTGRES_GATE_ALLOW_SHARED_SERVER=1`) — the guard exists because a run rewrote the
   live `audit_writer` password cluster-wide.
4. **`.105` hosts other projects' containers** (`accesstracker-*`, `technology-procurement-*`).
   Never stop, restart, prune or modify them.
5. **`docker exec` needs `-i`** for a heredoc, or stdin never reaches `psql` and it silently no-ops.
6. **A green plan is not a reviewed plan** (see the incident document).
7. **Never give the supervise worker a queue-depth scale rule, and never set its `min_replicas` to
   0.** Its retention, audit-anchor, ingestion and mailbox roles emit their own triggers from
   in-process wall-clock timers, so at zero replicas nothing is ever enqueued for such a rule to
   react to and the window is dropped. `main.tf` and
   `test_azure_nightly_shutdown_contract.py` both pin this.
8. **A confident comment is still an assumption.** Two defects this session traced to reasoning
   asserted in a comment and never checked: `revision_mode = "Multiple"` (~$889/mo of orphaned
   replicas) and "a queue rule waking a worker" (there are no scale rules at all — it hid a running
   replica for four nights). When a comment justifies skipping a check, verify the justification.
