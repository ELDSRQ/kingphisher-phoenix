# Build Review — QA Engineering + Human-User Pass (2026-09-27)

Scope: full-repo inspection of `main` (working tree clean at review time). Method:
static reading of apps/packages/scripts/infra, cross-checking every claim against
live code (grep-verified), not a test run. All findings below were verified in
the tree; nothing is copied from stale handoffs. Release status is unchanged:
**production/RSA NO-GO** per AGENTS.md — this report does not alter that.

---

# Part 1 — QA engineering review

## 1.1 What is solid (do not touch)

- **No orphan code.** All 12 packages are imported by runtime code; no dead
  libraries, no unused routers. Every UI route inspected (`app.js` → ~50 API
  endpoints) has a live backend handler.
- **Fail-closed discipline is real, not cosmetic.** Capability checks on every
  mutation route, server-derived action flags, masked secrets, CSRF origin
  checks, bounded streamed fetches, purpose-scoped bearer verifiers.
- **Test pyramid (backend) is deep**: ~2,700 hermetic tests, 836 in
  operator-api alone, plus ~25 UI-contract tests that pin console source to API
  behavior, plus a bundle-drift gate.
- **Error hygiene**: no silent exception swallowing found; the two broad
  `except BaseException` sites are resource-cleanup guards (correct); naive
  datetimes are consistently normalized to UTC.

## 1.4 Security posture notes

No new vulnerabilities found in static review; the documented boundaries
(auditor separation, no-audit-HMAC-to-runtime, bearer verifiers, WORM witness)
are consistently implemented. The residual risks are all *evidence* risks the
repo already tracks (browser/WCAG human pass, cloud gates, key-rotation debt)
plus one process note: the console password is a permanent secondary auth path
alongside OIDC with a manual rotation story (env var).

## 1.5 QA remediation plan

Ordered; each item small enough for one PR. P1 = do now, P2 = this cycle,
P3 = backlog.

**P1**
1. **Wire AUD-003 to the alert pipeline.** On gate trip, enqueue a
   `queue_dispatch` alert event through the existing alert provider
   (`providers/alerts.py`) so subscribed webhook/ntfy destinations fire. Add a
   hermetic test asserting a stale heartbeat produces an alert intent row.
   *(Closes F1.)*
2. **Surface scheduler state.** Add `scheduler: {enabled, last_run_at,
   last_result}` to the aggregation status payload and render it in the
   Aggregation view ("Automatic refresh is OFF — data is X hours old; run now
   or enable `OPERATOR_API_AGGREGATION_SCHEDULER_ENABLED`"). *(Closes F2.)*
3. **Add fetch timeout + single retry** to `api()`: `AbortSignal.timeout(30s)`,
   one automatic retry on network error for idempotent GETs, explicit "request
   timed out" message. *(Closes F9.)*

**P2**
4. **AI model pin self-check at worker start**: if
   `KP_WORKER_AI_BASE_URL` differs from the default while `KP_WORKER_AI_MODEL_ID`
   is unset, log a loud WARN naming the mismatch failure mode; extend the
   existing regression test to cover base-URL-change-without-pin-change.
   *(Closes F7.)*
5. **Structural test-time gate**: a tiny pytest plugin (or semgrep rule in the
   existing `tests/support/semgrep.yml`) rejecting datetime literals > 90 days
   in the future inside `tests/`. *(Closes F8.)*
6. **Console behavioral smoke in CI-able form**: extend
   `tests/e2e/console-nav.smoke.spec.mjs` to cover login → new-campaign prefill
   → needs-my-decision, and add a `docker-compose.e2e.yml`-based target
   (`make test-console-smoke`) that runs it against the disposable local stack
   so it can run without a manual tunnel. *(Closes F10 partially.)*
7. **Label the generated bundle**: prepend a visible banner comment to
   `src/console/app.js` build output ("GENERATED — edit src/console-js/"),
   enforced by the build script. *(Closes F4.)*
8. **Default a `KP_WORKER_DATABASE_URL_*` fallback**: allow `supervise` to fall
   back to the base `DATABASE_URL` with an explicit env flag
   (`KP_WORKER_SUPERVISE_SHARED_DB=1`) for single-tenant deployments, keeping
   the strict per-role requirement as default. *(Closes F5.)*

**P3**
9. **Archive stale handoffs**: move `AI_HANDOFF_2026-09-{11..19}.md`,
   `NEXT_AI_PROMPT.md`, `RESUME-HERE.md`, `AUDIT_REPORT_2026-09-14.md`,
   `QA_TASKS.md` (preserved copy) into `docs/archive/`; leave one
   `AI_HANDOFF.md` pointer file. No history deletion — a `git mv` only.
   *(Closes F6.)*
10. **Right-size telemetry**: remove `otel-collector` from the default compose
    profile (move to the `ai`-style opt-in profile) OR wire a real OTLP
    exporter into `kp_telemetry.logging` behind an env flag. Pick one; the
    current state is the worst of both. *(Closes F3.)*
11. **Finish U1 labeling**: route the remaining `slice(0,8)` sites through
    `recipientLabel`/`recipientPickerLabel` helpers. *(Closes F11.)*
12. **Mechanical app.js split** along the already-existing `views.*` function
    boundaries into per-view modules behind the same esbuild entry; the drift
    gate makes this verifiable. Do after P2 items so contract-test churn lands
    once. *(Closes F13.)*

Explicitly *not* recommended: adding a second JS framework, removing the
committed bundle, or enabling the aggregation scheduler by default without the
P1-2 visibility fix.

# Part 2 — Human-user review

Persona: one of the two IT staff operating a 125-person tenant. Performed as a
walkthrough of the console flow defined in `docs/START-HERE.md` cross-checked
against the actual view code and API behavior.

## 2.1 Overengineered / confusing for the target user

| # | Finding | Why it hurts |
|---|---------|--------------|
| H1 | **The Azure path exposes Terraform internals in the operator console** — three stages (`foundation_bootstrap`, `foundation_finalize`, `workloads`), digest-bound plans, advance/retry/rollback verbs. | A two-person IT team should never reason about Terraform stage semantics. This is deploy-engineering UI embedded in an operator product. |
| H2 | **Onboarding fronts six provider paths** (Mailpit, generic SMTP, ACS, M365 Graph directory, M365 reported mailbox, AI gateway) through one sequential wizard. | The wizard is well-built, but step 1 for a small tenant is "nothing yet, use the pretend inbox" — the wizard doesn't offer that as a first-class finish line. |
| H3 | **Three stop semantics**: Recall (campaign), Pause (scheduling), emergency stop (global/campaign kill switch). The distinction is explained in `OPERATOR-GUIDE.md` but in-console only as tooltip prose. | Under stress an operator must not choose between three red buttons by reading tooltips. |
| H4 | **Six launch verbs**: create → submit (= approval) → canary → verify → publish, plus approve-pattern and approve-draft upstream. START-HERE is honest, but the console still uses "submit", "review", "schedule", "publish", "canary" as separate button vocabularies. | Two-person teams think in "test send" and "send to everyone"; the gate is good, the words are engineering. |
| H5 | **Docs contradict the shipped mode.** `OPERATOR-GUIDE.md` still states "The person who created the campaign cannot approve their own work" as an unconditional two-person rule, while `single-operator` (the current `.105` mode) deliberately allows self-approval. | An operator reading the guide meets a UI that contradicts it; trust in the docs erodes exactly at the safety-critical topic. |
| H6 | **20 sidebar destinations** even after the "More" grouping. Sources, Threat workbench (activate/reject/merge-duplicate), Aggregation, Model control, Queues/dead-letters, Privacy DSR are power tools that a 125-user tenant touches a few times a year. | Grouping helped; the remaining cognitive load is the number of *things that exist*, not their location. |
| H7 | **Program Planner vocabulary**: "occurrences", "elapsed-day cadence", "forward-only pause/resume". | Jargon with no plain-language gloss in the view (the view copy improved in PR #72 but the model vocabulary remains). |

## 2.2 Too many steps — streamlining opportunities

1. **First campaign is ~11 interactions** (domain DNS wait → RoE sign → CSV
   import → approve pattern → wait for draft → approve draft → create → submit
   → canary → check Mailpit → publish). START-HERE's "four inputs" is truthful
   but the *confirmations* between them are invisible until encountered. The
   Campaigns page already computes what's missing — make that checklist the
   default landing view until first publish, with inline buttons per step, and
   the same page becomes the launch console.
2. **RoE re-signing per window**: the prefill and "re-sign for a new window"
   exist (UX-011 §4); the residual step is navigating to Domains & RoE when a
   campaign is blocked — the Campaigns page's "what's missing" links already
   do this; verify every block reason has such a link (they do for RoE and
   audience; confirm for terms-acknowledgement and lesson binding).
3. **Draft approval double-trip**: pattern approval and draft approval are two
   separate pages. A combined "review the lure and its generated draft" flow on
   one screen (both decisions are the same actor in single-operator mode) would
   halve the round trips without touching the audit trail.

## 2.4 Human-experience remediation plan

**Phase 1 — words and defaults (console-only, S each)**
1. Mode-aware guide fix (H5): one paragraph in `OPERATOR-GUIDE.md` + a console
   Help note stating what `single-operator` changes (self-approval recorded as
   `self_approved`), and what it does *not* change (canary gate, RoE, audit).
2. Launch verb simplification (H4): rename visible buttons to
   "Send test to canary" and "Send to everyone"; keep "canary/publish" as
   secondary text. Contract tests updated in the same PR.
3. Stop-control consolidation (H3): one "Stop" control with two scopes
   (This campaign → recall+pause; Everything → kill switch), each with a
   one-line consequence statement instead of three separate affordances in
   different views.
4. Bundle banner (P2-7 above) also prevents the "edited the wrong file" class
   of human error.

**Phase 2 — flow (M)**
5. First-campaign checklist as default landing view (§2.2-1) — reuses existing
   readiness computation; adds zero endpoints.
6. Combined pattern+draft review screen for single-operator mode (§2.2-3) —
   server already supports both decisions independently; this is a view.
7. Post-publish closure banner (H11).

**Phase 3 — behavior (L, gate review each)**
8. Decision-needed notifications (H8) — one default alert subscription created
   during onboarding; hermetic test for the trigger condition.
9. Send-time spread (H9) — per UX-011 §6 design, delivered as a bounded
   integer field + delivery-side pacing; provider-correlation evidence
   requirements unchanged.
10. Weekly digest (H10) — behind an env flag, off by default, reusing the
    alert provider.
11. Azure console surface reduction (H1) — long-term: keep the deployment
    wizard but collapse it to "Connect Azure / Status / Advanced" with the
    three stages as an Advanced disclosure. Requires no backend change; the
    digest-bound plan semantics stay.

**Deliberately not proposed:** removing the canary gate, merging approval with
creation in ENFORCE mode, auto-publishing, or deleting deferred power views
(Threats/Sources/Programs stay — policy explicitly retains deferred
functionality; the fix is placement and language, not amputation).
